## Task 4 — Lexical leakage / overlap

**Verdict: unclear as a leakage claim; no leakage is established by overlap alone.** BM25 complete-support successes do have higher mean overlap overall (0.718 vs 0.397), but hop count and passage wording are confounders; the 2-hop separation is small, and 3-hop has no strict successes to compare.

For each of 98 answerable questions, content words are unique BM25-tokenized question terms after a fixed stopword list; overlap is the fraction of those terms present in the union of each gold passage title+text, averaged across all gold passages for that question. BM25 “success” means strict complete-support recall@5 = 1.0; “incomplete” means <1.0. This is lexical overlap, not proof of benchmark leakage.

1. **Dense truncation:** encode long passages as overlapping windows up to the model token limit, mean-pool and renormalize per passage; add an embedding-strategy cache version so old truncated caches cannot be reused. Passage IDs and row order stay unchanged.

## Limits / additional evidence needed

- Windowing recovers +0.049 dense recall@5 overall, but the remaining 0.325 gap to BM25 and residual BM25-success/dense-failure examples mean truncation is not the only factor. Comparing max-window scoring, a stronger retrieval model, and question/passage semantic fit is needed before making a broader dense-quality claim.
- Graph results need a full-coverage graph built from the same 10,878-passage domain corpus. The current 20-paper pilot does not pass the coverage condition for a graph quality claim.
- The config says 500 tokens while the current passage generator uses 500 words. Correcting chunking requires a new corpus version and new passage-to-gold mapping; this report did not alter frozen evaluation data.
